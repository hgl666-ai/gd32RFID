### 模型1: 协议解析状态机 (protocol.c, 7状态13转移)
- 通过: S1可达性 / S2无死锁 / S4确定性 / S6守卫完备 / S7不变量(帧头必须在数据态/CRC态之前,
  A5->5A->CMD 顺序) / A2 / A4 / A5边界 / A6 / A7无最短反例 / A10序列顺序。
- S3"闭合SCC无终态"= 解析器是永续反应式机器(帧结束后回S0等下一帧), 属设计行为非缺陷。
- S5/A1"64个未处理事件对"= 建模抽象产物: 真实代码每状态都消费任意字节并按值分发
  (S0的O分支覆盖所有非A5字节, S2任意字节即CMD), 不存在真正被忽略的字节。
- A3"顺序敏感"= 字节流解析器本质上顺序敏感(A5 5A必须按序), 属设计行为。
- 结论: 无功能性缺陷, 不改代码。
