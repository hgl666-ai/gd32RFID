## 2026-09-16(续14) ★深思考复核: SWD假设重新成为首要嫌疑 + blink探针★
- 重读 `FM15L013技术手册` 的 PAD 模块章节(3.3.4), 关键原文:
  * "注：gpio0 和 gpio1 的通路选择在 SWD 接口启用条件下无论配置何值，都默认走 SWD 通道。"
  * GPIO_PAD_SEL0(0x00E6_0300) 复位值 **0x0000_0000** = 所有 PAD 默认走 **gpio**(0x0:gpio / 0xF:reset_n);
    GPIO_PAD_SEL1 也是 0x00000000。⇒ 默认是GPIO, 但**前提是"SWD接口未启用"**。
  * 本板接线: 读卡器 **SCL → SE pin6 = GPIO0**, 读卡器 NPD → SE pin7 = GPIO1;
    而 pin6/pin7 的复用名正是 **SWCLK/SWIO**。
  ⇒ 若这颗SE的 **SWD 接口处于启用态**(未锁定), GPIO0 被 SWCLK 占用, SE **物理上无法给读卡器提供时钟**
    ⇒ 读卡器在任何地址都不应答(112/112全0x9EFA) ✓、与所有参数无关 ✓、
      且每条 set_tag_reader 的 **106~159ms 恰好=按寄存器逐个超时** ✓ —— 与全部现象吻合。
- **之前否定该假设的依据不成立**: 用户是在 **100ms/格** 下看到"波形密集持续";
  该时基下 I2C 突发(几 ms)应表现为**稀疏小突波**, 而"密集持续"恰是**射频串扰**(13.56M/27M)的样子;
  且我们固件在启动后**不再发任何读卡器命令**, "开机后一直持续"与固件行为不符。
  ⇒ **必须用 1~10µs/格 复测**, 之前的"SCL有波形"不能作为否定依据。
- 新增诊断模式 **RFID_DIAG_BLINK_PROBE**(debug_config.h, 当前=1):
  `se_reader_blink_probe()`: 每轮 LED(PA5/SYS_LED) 闪6下做视觉标记 → 紧接着发一条 set_tag_reader(0x28)
  → 打印 SW/dt + PA4(让成输入后)的读数 → 重新认证 → 等1s → 循环(不返回, 但循环内仍调 app_uart_rx_task)。
  用途: 示波器探头放 RFID_SCL(SE pin6/FM17622 pin31), **LED闪完那一段就是读卡器访问波形**,
        不用猜时刻; 同时验证读卡器是否只是"需要更久才就绪"。
  判据: SCL有串方波 ⇒ SE在驱动 ⇒ SWD未占用; **SCL平而SDA有方波 ⇒ GPIO0被SWD占用(=根因)**。
  另: PA4(Hi-Z)读到0 ⇒ GPIO1是可用GPIO ⇒ 可反证SWD未占用(读到1则无区分力)。
